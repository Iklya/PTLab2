# Лабораторная работа №2

## Постановка задачи

Разработать веб-приложение на Django для учета товаров, покупателей и покупок в магазине.

В рамках лабораторной работы необходимо реализовать веб-приложение интернет-магазина, в рамках которого пользователь может просматривать каталог товаров, добавлять товары в корзину, удалять их, выбирать существующего покупателя или создавать нового, а затем оформлять заказ.

Корзина хранится в сессии пользователя. Скидка рассчитывается по общей стоимости товаров в текущей корзине, а не по истории предыдущих покупок.

| Сумма товаров в корзине | Скидка |
| ----------------------- | ------ |
| менее 5 000 ₽           | 0%     |
| от 5 000 ₽              | 3%     |
| от 10 000 ₽             | 5%     |
| от 20 000 ₽             | 10%    |

## Модели данных

В приложении `shop` используются три модели.

### Product

Модель товара содержит: - `name` — название товара; - `price` — цена
товара.

### Customer

Модель покупателя содержит: - `name` — имя покупателя; - `address` —
адрес покупателя.

Метод `total_spent()` возвращает историческую сумму покупок покупателя.
Эта величина не используется для определения скидки на текущий заказ.

### Purchase

Модель покупки связывает покупателя и приобретённый товар. Дата покупки
устанавливается автоматически.

## Основные возможности

### Каталог товаров

На главной странице отображается список товаров, добавленных через
панель администратора Django.

### Работа с покупателями

Пользователь может выбрать покупателя из выпадающего списка или перейти
к форме создания нового покупателя. После создания новый покупатель
автоматически выбирается для текущей сессии.

### Корзина

Добавление и удаление товаров выполняется через POST-запросы. Содержимое
корзины хранится в сессии. Один и тот же товар можно добавить несколько
раз.

На странице отображаются: - список товаров в корзине; - общая
стоимость; - процент скидки; - сумма скидки; - итоговая стоимость
заказа.

### Оформление заказа

Перед подтверждением заказа отображается страница проверки состава
корзины и выбранного покупателя. После подтверждения для каждого товара
создаётся отдельная запись `Purchase`.

Создание записей выполняется в транзакции базы данных. После успешного
оформления корзина очищается, а пользователь видит страницу
подтверждения заказа.

## URL-маршруты

  URL                         Назначение
  --------------------------- -------------------------------------
  `/`                         Главная страница, каталог и корзина
  `/customer/add/`            Создание покупателя
  `/customer/select/`         Выбор покупателя
  `/cart/add/<product_id>/`   Добавление товара в корзину
  `/cart/remove/<index>/`     Удаление товара из корзины
  `/buy/`                     Проверка и оформление заказа
  `/admin/`                   Панель администратора Django

## Тестирование

Для проверки приложения используются модульные тесты Django. Тесты
разделены по назначению:

-   `test_models.py` — создание моделей, поля, строковое
    представление, связи между моделями, историческая сумма покупок и
    каскадное удаление;
-   `test_urls.py` — проверка разрешения URL-маршрутов на
    соответствующие представления;
-   `test_views.py` — проверка главной страницы, расчёта скидок,
    операций с корзиной, выбора и создания покупателя, а также
    оформления заказа.
    
## Непрерывная интеграция

В репозитории настроен GitHub Actions. Workflow находится в
`.github/workflows/django.yml`.

При запуске workflow подготавливается окружение Python и PostgreSQL,
устанавливаются зависимости, после чего выполняются проверки Django и
тесты приложения. Параметры подключения к тестовой базе задаются через
переменные окружения workflow.
